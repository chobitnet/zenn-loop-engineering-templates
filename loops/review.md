# loop: review — 振り返る役。週次メトリクスと自己改善のループ

## 使い方

- `__PLACEHOLDER__` を置き換える。
- 感覚ではなく実数で測る。取れない数値は「未計測」と書く。
- 撤退線は数字で引く。
- 分析だけで終わらせず、次週のループ定義と memory へ改善を書き戻す。

- 頻度: 週1。曜日固定
- 目的: 実数で進捗を測り、ハーネス自身を改善する。感覚ではなく数字で撤退線を引く。

## 計測ファネル

何を数えるかを先に固定する。ファネルの段ごとに、どの数値をどこから取るかを書く。

| 段 | 数値 | 取得元 |
|---|---|---|
| 露出 | __IMPRESSIONS__ | __SOURCE__ |
| 流入 | __VISITS__ | __SOURCE__ |
| 反応 | __REACTIONS__ | __SOURCE__ |
| 収益 | 台帳の実収益のみ | metrics/ledger.md |

## 手順

1. memory/review.md と前週のレポート・台帳を読む。
2. ファネルの各数値を収集する。**取れないものは「未計測」と明記**する。ゼロと未計測は別物である。
   未計測を放置しない。「計測できていない」は改善課題として書く。
3. 前週比・傾向を1枚にまとめ、reports/YYYY-MM-DD/HHMM-review.md に書く。
4. **改善の書き戻し**: 分析から出た改善を、該当ループの memory への申し送りか、loops/*.md の
   手順修正として、戦術の範囲で実際に書き込む。レポートに書くだけで終わらせない。
   ファイルに書き戻して初めてループの挙動が変わる。
5. 目標・撤退線のような戦略に関わる発見は、判定日を待つ。前提を壊す事実なら decisions/open へ起票する。

## 撤退線の運用

- 「うまくいっていない」を数字で言える形にしておく。
- 支出を承認するときは撤退条件を同時に決め、判定日に見直す。
- 撤退線のない施策を始めない。
