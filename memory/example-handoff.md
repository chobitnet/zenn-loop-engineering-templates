# memory/__LOOP_NAME__.md の実例抜粋テンプレート。引き継ぎが効いた形

## 使い方

- 4点フォーマット「やったこと / 効いたこと / 効かなかったこと / 次回への引き継ぎ」の書きぶりの見本である。
  2節とも一般化した実例で、自分のループの実記録で置き換えていく。
- 見出しの4点は固定し、増減しない。
- 引き継ぎには、次回が最初に読んで動ける具体を書く。場所、値、扱いの区別。

## YYYY-MM-DD 実行(記事執筆)

### やったこと

1. 記事第N回の草稿を執筆、公開キューへ。
2. 執筆指示に含まれていた実績数値を一次記録に照合。対象リポジトリの初回コミット日と
   データ側の最古タイムスタンプから、指示の数値が実際より長いと判明。記事は実測値で書き、指示側の
   出典ファイルにも訂正候補として申し送った。

### 効いたこと

- **「実績数値は、指示に書いてあっても必ず一次記録に当てる」の規則**。感覚や上流文書を信用せず
  照合したから捕捉できた。

### 効かなかったこと

- 照合に使える一次記録がどこにあるかを探すのに時間を使った。
  → 照合先の場所そのものを下の引き継ぎに書いて次回へ渡す。

### 次回への引き継ぎ

1. 実績数値の照合先: リポジトリは `git log --reverse` の初回コミット日、データは
   ファイルのメタデータ最古値。この2つを一次とする。
2. 上流文書の数値は「出典」ではなく「照合対象」として扱うこと。

## YYYY-MM-DD 実行(プラットフォーム規約調査)

### やったこと

1. 販売プラットフォームの規約・手数料を調査。**一次情報で確認できた項目**と、
   **複数の二次情報が一致しているだけの項目**を分けて記録した。前者は公式規約ページで確認した項目、
   後者は手数料率。

### 効いたこと

- 前回の別プラットフォーム調査の失敗が memory に残っていたため、今回は最初から「一次/二次」を分けて書けた。
  前回は二次情報同士の矛盾を決定材料にしかけていた。

### 効かなかったこと

- 手数料の一次ページがクライアントレンダリングで機械取得できず、二次一致どまり。
  「一次確認済み」とは書かず、オーナーの登録時に管理画面で確認するよう申し送った。

### 次回への引き継ぎ

1. 手数料は二次一致どまり。未確定扱い。オーナーが登録する際に一次確認して、この節を更新すること。
