## 背景

整備した `.claude/settings.json` の許可リスト14件が、定時実行のランナーでは**無効化**されている。
ランナーはスケジューラが起動する非対話セッションである。ランナーログの原文:

> Ignoring 14 permissions.allow entries from .claude/settings.json: this workspace has not been trusted.
> Run Claude Code interactively here once and accept the trust dialog, or set
> projects["<ハーネスの絶対パス>"].hasTrustDialogAccepted: true in ~/.claude.json

許可リスト整備の際に、信頼ダイアログの承諾が別途必要なことが漏れていた。
ループが自分で `~/.claude.json` を書き換えるのは権限の自己拡張にあたるため行わない。

## 選択肢

1. ★ **ハーネスのディレクトリで Claude Code を対話起動し、信頼ダイアログを承諾する**。1分。正規の手順
2. **`~/.claude.json` に `hasTrustDialogAccepted: true` を手で追記する**。結果は同じだが手編集ミスのリスクあり

「信頼しない」を選ぶと、定時実行はファイル読み書きのみの縮退運用が恒常化する。許可リストを
承認済みの経緯からこの選択肢は現実的でないため挙げない。

## 追記。同日の対話セッション: 同時に必要な人間作業がもう1件

定時実行のランナーのプロセスがオーナーの書類フォルダ配下へアクセスした際、macOSのプライバシー保護の
ダイアログ「〜が書類フォルダへのアクセスを求めています」が発生。スケジューラ起動プロセスはターミナルの
許可を引き継がないため初回に必ず出る。無人実行を止める壁のうち「OSのプライバシー保護」にあたる。

1. 信頼フラグ: 上の選択肢1を実行
2. プライバシー保護のダイアログ: 「許可」を押す。出なくなった場合はシステム設定 > プライバシーとセキュリティ >
   ファイルとフォルダ で該当バイナリに書類フォルダを許可

## 解決。翌朝、人間が記入
